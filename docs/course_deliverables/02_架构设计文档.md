## 一、 架构愿景与设计原则

easySVA 旨在打造一款**低延迟、高内聚、易扩展、软硬解耦**的轻量化工业级边缘 AI 视频分析中台。系统遵循以下架构原则：
1. **微服务与容器化解耦**：业务逻辑层（Java/Spring Boot）、媒体分发层（C++/ZLMediaKit）、智能分析层（C++/ONNX Runtime）与交互展示层（Vue.js）独立解耦，且全栈已实现 Docker 容器化微服务编排。
2. **异构协议适配中台化**：屏蔽安防硬件厂商差异，通过 GB/T 28181-2016、RTSP 双流网关以及工位电脑摄像头 WebM 中继网关抹平差异，为上层应用提供标准 HTTP-FLV / WebRTC / RTMP 流。
3. **算法超参数动态热更新 (Hot-Reload)**：分析引擎支持在线动态调节置信度、角度及持续帧数，避免因视场差异频繁重编译或重启服务。
4. **零延迟与时钟同步导向**：视频全链路贯穿 PES PTS 硬件级时间戳同步与 0 缓存编码管线，确保算法推理与人工监视毫秒级协同。
5. **弹性算力与绿色节能**：引入算法流按需唤醒与休眠策略，平衡算力消耗与实时监管需求。

## 四、 关键数据流与拓扑交互设计

### 4.1 视频点播与播放全链路拓扑
```mermaid
sequenceDiagram
    autonumber
    actor User as 用户 (浏览器)
    participant Web as SVA-web (前端)
    participant Java as SVA-backend (Java)
    participant GbSip as GbSipServer (SIP)
    participant ZLM as ZLMediaKit (媒体服务)
    participant Sim as 国标模拟器/真实IPC

    User->>Web: 打开「实时监控」点击国标设备播放
    Web->>Java: GET /waring/device/list
    Java-->>Web: 返回播放地址 (如 http://127.0.0.1:9992/live/34020000001320000003.live.flv)
    Web->>ZLM: flv.js 发起 HTTP-FLV 拉流请求
    alt 流尚未建立 (无人推流)
        ZLM->>GbSip: 触发 on_play / hook 事件
        GbSip->>Sim: 发送 SIP INVITE (请求媒体传输)
        Sim-->>GbSip: 200 OK (携带媒体端口)
        GbSip->>Sim: 发送 SIP ACK
        Sim->>ZLM: 通过 RTP/UDP 推送 MPEG-PS 视频流
    end
    ZLM-->>Web: 持续推送 HTTP-FLV 纯视频帧切片
    Web-->>User: 毫秒级首屏秒开渲染
```

### 4.2 国标 PTZ 云台控制信令链路
```mermaid
sequenceDiagram
    autonumber
    actor User as 用户 (点击八向雷盘)
    participant Web as SVA-web 前端
    participant Java as SVA-backend
    participant Sim as 国标设备 (IPC)

    par 前端视口平滑反馈
        Web->>Web: 触发 CSS GPU scale(zoom) translate(panX, panY)
    and 后端协议信令透传
        Web->>Java: POST /waring/device/ptz/{apeId} {command: "up", speed: 32}
        Java->>Java: 生成 GB/T 28181 8字节Hex码: A50F0108002000D7
        Java->>Sim: UDP 发送 SIP MESSAGE (<PTZCmd>A50F0108002000D7</PTZCmd>)

        Sim-->>Java: SIP 200 OK
        Java-->>Web: 返回 HTTP 200 {code: 200, data: {ptzCmd: "A50F0108002000D7"}}
    end
    Web->>User: 终端回显指令与成功徽标
```

### 4.3 YOLO-Pose 算法超参数动态热重载链路 (Hot-Reload)
```mermaid
sequenceDiagram
    autonumber
    actor Engineer as 算法工程师 (前端)
    participant Modal as 算法调优弹窗 (AlgorithmConfigModal)
    participant Java as 后端 (AlgorithmTuningController)
    participant Server as C++ Server (HTTP: 9993)
    participant Sched as C++ 调度器 (Scheduler)
    participant Workers as 推理线程池 (Workers 1..N)

    Engineer->>Modal: 调节滑块 (如 sleep_torso_angle=35, frame_thresh=75)
    Engineer->>Modal: 点击【应用生效】
    Modal->>Java: POST /waring/algorithm/config/update {config}
    Java->>Server: POST http://127.0.0.1:9993/api/control/update_algorithm_config
    Server->>Sched: update_algorithm_config(new_cfg)
    loop 遍历所有活跃 Worker
        Sched->>Workers: worker->update_config(new_cfg) (读写锁保护更新)
    end
    Workers-->>Sched: 配置热加载成功 (0 丢帧 0 重启)
    Sched-->>Server: return OK
    Server-->>Java: 200 OK {"code": 0, "msg": "success"}
    Java-->>Modal: 200 OK (提示“算法参数更新成功”)
    Modal-->>Engineer: 界面回显绿色当前生效配置
```

### 6.1 容器协同与通信规范
1. **统一网络命名空间**：所有 7 个容器挂载于同一个 Docker 桥接网络 `easysva-net`，容器间直接利用服务名解析（如 `sva-mysql`、`sva-media`、`sva-analyzer`），杜绝 IP 硬编码。
2. **三级存储卷持久化**：
   - `mysql-data`：持久化 MySQL 表结构、设备记录及告警历史；
   - `redis-data`：持久化会话与状态缓存；
   - `sva-upload`：在 `sva-backend`、`sva-analyzer` 与 `sva-web` 之间共享，确保算法抓拍的现场图片可瞬间被后端记录并被前端 Nginx 访问展示。
3. **GPU 自适应回退**：`sva-analyzer` 镜像内置探测逻辑，若检测到 NVIDIA GPU 驱动则开启硬加速；若无显卡则自动降级使用 CPU `libx264` 软编码，输出日志提示并不中断服务。
