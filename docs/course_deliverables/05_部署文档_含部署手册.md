## 一、 部署架构与软硬件环境基准

### 1.1 硬件配置最低要求
- **CPU**：4 核 x86_64 处理器（推荐 8 核及以上）
- **内存 (RAM)**：最低 8GB（推荐 16GB，用于支撑多路并发 AI 姿态估计）
- **硬盘存储**：SSD 可用空间 $\ge 20\text{GB}$（用于存放测试视频、模型权重与告警截图）
- **网络环境**：支持本地回环通信（`127.0.0.1`），开放 UDP 5060/15060 及 TCP 80/9114/9992 端口

### 1.2 操作系统与运行环境
- **操作系统**：Ubuntu 22.04 LTS（原生 Linux 或 Windows 11 WSL2 均可）
- **开发与运行时依赖**：
  - **C++ 工具链**：GCC / G++ 11.4+, CMake 3.22+
  - **Java 运行环境**：OpenJDK 1.8 (Java 8) 或 OpenJDK 11
  - **前端构建工具**：Node.js v16.x + NPM 8.x
  - **Python 运行时**：Python 3.10+（包含 `requests`, `urllib3`, `opencv-python`）
  - **数据库**：MySQL 8.0.x
  - **缓存中间件**：Redis 6.x / 7.x
  - **Web 反向代理**：Nginx 1.18+
  - **音视频核心库**：FFmpeg 4.4+, OpenCV 4.5.4, ONNX Runtime 1.12+

## 三、 核心子系统编译与部署步骤

### 3.1 ZLMediaKit 与国标 SIP 服务编译与运行
```bash
# 进入工程目录编译
cd /opt/SVA/SVA-backend/SVA-mediaServer
mkdir -p build && cd build
cmake .. -DENABLE_WEBRTC=true -DENABLE_GB28181=true
make -j$(nproc)

# 产物部署至 /opt/SVA/mediaServer 目录
mkdir -p /opt/SVA/mediaServer
cp -r ../release/linux/Release/* /opt/SVA/mediaServer/
```

### 3.2 C++ SVA-server 推理服务编译
```bash
cd /opt/SVA/SVA-server
mkdir -p build && cd build
cmake .. -DCMAKE_BUILD_TYPE=Release
make -j$(nproc)

# 产物部署
cp Analyzer /opt/SVA/server/
cp -r ../models /opt/SVA/
```

### 3.3 Java SVA-backend 后端打包与部署
```bash
cd /opt/SVA/SVA-backend/SVA-backend
# 使用 Maven 进行单体打包，跳过测试
mvn clean package -DskipTests

# 部署至执行目录
cp ruoyi-admin/target/ruoyi-admin.jar /opt/SVA/backend/backend.jar
```

### 3.4 Vue SVA-web 前端编译与 Nginx 发布
```bash
cd /var/www/SVA-web
# 针对 Node 17+ / OpenSSL 3 注入 Legacy 参数，避免数字签名报错
sudo env NODE_OPTIONS='--openssl-legacy-provider' npm run build:prod

# 确认产物已更新至 /var/www/SVA-web/dist
ls -la /var/www/SVA-web/dist/index.html

# 重新加载 Nginx 配置
sudo nginx -t && sudo nginx -s reload
```

## 四、 自动化运维与一键启停控制

项目提供了标准化一键管理脚本体系，杜绝人工依次拉起各服务可能产生的时序依赖错误：

### 4.1 全系统一键自愈启动 (`restart.sh`)
```bash
sudo /opt/SVA/restart.sh
```
**`restart.sh` 标准执行拓扑流程 (7步保障)**：
1. **[1/7] 全量进程清理**：强制杀死遗留的 MediaServer, GbSipServer, Analyzer, Java backend, FFmpeg 及模拟器进程，清除悬挂端口与死锁。
2. **[2/7] 启动 ZLMediaKit**：启动流媒体主引擎（监听 9992, 9994, 9995）。
3. **[3/7] 启动 GbSipServer**：开启国标 SIP 信令服务（监听 UDP 5060, HTTP 19114）。
4. **[4/7] 启动 FFmpeg 测试流与国标模拟器**：
   - 循环推流测试源 `/opt/SVA/media/sleep_source.mp4` 到 RTMP `live/sleep_test`；
   - 启动 Python 国标模拟器注册上线；
   - 启动转桥守护进程，保证通道畅通。
5. **[5/7] 启动 C++ Analyzer**：加载 YOLO-Pose 姿态模型，监听视频分析指令。
6. **[6/7] 启动 Java 后端**：`java -jar /opt/SVA/backend/backend.jar` 并等待 9114 端口健康就绪。
7. **[7/7] 重载 Nginx 反代**：刷新静态资源与流代理路由。

## 五、 双专项终端监控大屏使用手册

针对系统运行态势感知，系统内置了两个双 2 秒高刷新的 ASCII 终端控制看板，只读运行，绝不侵占服务端口：

### 5.1 本地 6 核心服务监控看板 (`sva_monitor.sh`)
```bash
# 启动常驻监控大屏 (按 Ctrl+C 退出，不影响后台)
bash /opt/SVA/sva_monitor.sh

# 或单帧自动化巡检输出
ONESHOT=1 bash /opt/SVA/sva_monitor.sh
```
**面板展示项**：
- **服务健康度**：Java Backend, ZLMediaKit, Analyzer, MySQL, Redis, Nginx 运行状态（绿点 OK / 红点 DOWN）；
- **进程与系统开销**：各核心组件 PID、系统 CPU 使用率、物理内存消耗；
- **业务负荷**：当前活跃布控任务数、ZLM 正在分发的流媒体路数、累计告警入库数量。

### 5.2 国标设备专项监控看板 (`gb_monitor.sh`)
```bash
# 启动国标专项监控
bash /opt/SVA/gb_monitor.sh
```
**面板展示项**：
- **SIP 注册状态**：设备国标 ID、通道 ID、注册存续时长；
- **心跳倒计时**：15 秒保活心跳倒计时进度，超过 45 秒高亮告警；
- **点播与推流会话**：活跃 Session ID、流媒体传输协议及实时比特率；
- **信令计数统计**：REGISTER 次数、Keepalive 次数、INVITE 响应次数、**PTZ-CONTROL 控制次数**。

## 六、 常见故障排查手册 (Troubleshooting FAQ)

### Q1: 视频监控画面黑屏或显示“加载中”？
- **排查步骤**：
  1. 运行 `ONESHOT=1 bash /opt/SVA/gb_monitor.sh` 查看国标会话是否存在；
  2. 若会话显示已在推流但浏览器黑屏，多半为旧进程残留导致的 Session 悬挂；
  3. **解决方案**：执行 `sudo /opt/SVA/restart.sh` 执行全量自愈重启，清空旧 session。

### Q2: 模拟器启动报错 `Permission denied: /opt/SVA/simulator.log`？
- **原因**：此前使用了普通用户直接输出日志，权限受限。
- **解决方案**：脚本已更新为 `sudo bash -c "nohup ... > /opt/SVA/simulator.log 2>&1 &"`，确保全局可写。

### Q3: 前端编译报错 `ERR_OSSL_EVP_UNSUPPORTED`？
- **原因**：Node.js 17+ 引入了 OpenSSL 3.0，对旧版 Webpack 加密算法限制严格。
- **解决方案**：必须在执行命令前追加环境变量：  
  `sudo env NODE_OPTIONS='--openssl-legacy-provider' npm run build:prod`
