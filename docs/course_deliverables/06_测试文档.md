## 三、 核心模块功能测试用例与实测记录

### 用例 1：YOLO-Pose 睡岗检测时序抗干扰测试
| 测试编号 | TC-POSE-01 | 测试模块 | C++ Analyzer / YOLO-Pose |
| :--- | :--- | :--- | :--- |
| **测试场景** | 验证算法是否能够准确区分“短暂正常低头”与“长时间沉睡趴桌” |
| **输入条件** | 1080P 工位监控视频流，测试人员分别做动作：<br>1. 抬头端坐；<br>2. 低头喝水捡笔（持续 2 秒后抬起）；<br>3. 伏案趴在桌上（持续 8 秒）。 |
| **预期结果** | 喝水捡笔动作在 2 秒内恢复，不触发告警；伏案趴桌在满 5 秒时精准触发告警并截图。 |
| **实测结果** | **符合预期**。2 秒低头时计数器升至 50 帧后回落归零，未产生误报；趴桌第 125 帧时触发 `sleep_pose` 告警，前端收到告警弹窗与骨骼线标注截图。 |

## 四、 视频卡顿优化前后性能对比评测

针对初期系统存在的视频播放卡顿与累积延迟问题，QA 团队进行了严谨的对比基准测试：

| 评测维度 | 优化前指标 | 优化后指标 | 改善幅度 | 核心原因分析 |
| :--- | :---: | :---: | :---: | :--- |
| **端到端视频延迟** | 2800 ms | **360 ms** | **降低 87.1%** | 关闭 flv.js IO 缓冲 (`enableStashBuffer: false`)，编码器开启 `-tune zerolatency` |
| **首帧秒开耗时** | 2200 ms | **420 ms** | **缩短 80.9%** | 强制 1 秒短 GOP (`-g 25`)，前端快速命中 IDR 关键帧即解即播 |
| **长时间播放内存占用** | 持续爬升至 1.8GB (崩溃) | **稳定在 160MB** | **彻底杜绝泄漏** | MSE 开启 `autoCleanupSourceBuffer: true`，仅保留最近 5~15s 分片 |
| **音视频同步稳定性** | 每隔 10s 假死卡顿一次 | **持续流畅 0 卡顿** | **完全消除** | 强制声明 `hasAudio: false`，规避无音频流时的 A/V Sync 等待挂起 |
| **时间戳抖动 (Jitter)**| 方差 $\sigma^2 = 142.5$ | **方差 $\sigma^2 = 0.02$**| **消除抖动** | 解析真实 MPEG-PS PES PTS 替代累加包数合成时间戳 |
