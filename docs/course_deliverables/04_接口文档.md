## 一、 接口设计通则与规范

1. **通信协议**：HTTP/1.1、RESTful API 架构风格。
2. **字符编码**：UTF-8。
3. **鉴权机制**：基于 HTTP Header `Authorization: Bearer <token>` 传递 JWT 认证凭据。
4. **统一响应格式**：
```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {}
}
```
- `code`: 状态码，`200` 代表成功，`401` 代表凭证无效，`500` 代表业务或系统异常。
- `msg`: 文本提示信息。
- `data`: 业务负载对象或数组。

## 二、 设备管理接口族 (Device APIs)

### 2.1 分页查询设备列表
- **接口地址**：`GET /waring/device/list`
- **请求参数**：`pageNum` (页码), `pageSize` (每页条数), `deviceName` (名称检索), `streamSourceType` (`DIRECT`/`GB28181`), `isOnline` (`0`/`1`)。

### 2.2 从流媒体同步国标设备
- **接口地址**：`POST /waring/device/gb28181/sync`
- **说明**：触发后端调用 GbSipServer 获取当前注册的国标设备列表，去重写入数据库。
- **响应示例**：
```json
{
  "code": 200,
  "msg": "同步国标设备成功",
  "data": {
    "totalSynced": 2,
    "inserted": 0,
    "updated": 2
  }
}
```

### 2.3 国标云台 PTZ 控制接口
- **接口地址**：`POST /waring/device/ptz/{apeId}`
- **说明**：向指定国标设备下发 8 字节云台控制信令。
- **请求 Body**：
```json
{
  "command": "up",
  "speed": 32
}
```
- **字段说明**：
  - `command`: 控制动作，支持 `up`, `down`, `left`, `right`, `upleft`, `upright`, `downleft`, `downright`, `zoomin`, `zoomout`, `stop`, `reset`。
  - `speed`: 速度档位（1~255）。
- **响应示例**：
```json
{
  "code": 200,
  "msg": "PTZ指令已下发",
  "data": {
    "ptzCmd": "A50F0108002000D7",
    "command": "up",
    "speed": 32
  }
}
```

## 四、 算法参数在线动态热重载接口族 (Hot-Reload APIs)

### 4.1 查询算法调参编辑值与最近一次下发回执
- **接口地址**：`GET /waring/algorithm/config`
- **调用方**：前端「算法参数调节」弹窗打开时调用。
- **说明**：接口返回的是编辑默认值、最近一次下发回执及参数范围。`current` 固定为 `null`，因为后端不能仅凭内存状态证明正在运行的 Analyzer 已采用某组参数；需要以本次下发回执和 Analyzer 返回的实际布控列表为准。
- **响应示例**：
```json
{
  "code": 200,
  "msg": "查询成功",
  "data": {
    "current": null,
    "configurationState": "UNVERIFIED",
    "persistence": "RUNTIME_ONLY",
    "defaultConfig": {
      "preset": "MEDIUM",
      "controlCode": "*",
      "detectionConfidence": 0.35,
      "nmsThreshold": 0.45,
      "confirmWindowSec": 15.0,
      "sleepPositiveRatio": 0.8
    },
    "lastApplied": null
  }
}
```

### 4.2 在线热更新算法超参数配置
- **接口地址**：`POST /waring/algorithm/config/update`
- **调用方**：前端「算法参数调节」弹窗点击【应用生效】时调用。
- **作用范围**：`controlCode="*"` 更新所有正在运行且已启用睡岗规则的布控；填写具体布控编号时只更新该布控的睡岗规则。`detectionConfidence` 与 `nmsThreshold` 属于共享 Pose 模型参数，只能随 `controlCode="*"` 下发。
- **配置生命周期**：热更新只作用于当前运行的 Analyzer。后端只保存最近一次下发回执（`RUNTIME_ONLY`），不把回执当作 Analyzer 的实时配置；重启 Analyzer 或重新启动布控后，应重新应用并重新核验。
- **请求 Body**：
```json
{
  "preset": "MEDIUM",
  "controlCode": "*",
  "detectionConfidence": 0.35,
  "nmsThreshold": 0.45,
  "keypointConfidence": 0.35,
  "confirmWindowSec": 15.0,
  "sleepPositiveRatio": 0.8,
  "headHeightRatioMax": 0.48,
  "headArmDistanceRatioMax": 0.75,
  "headMotionRatioMax": 0.15,
  "recoveryMs": 2000,
  "torsoAngleDegMin": 25.0,
  "shoulderTiltDegMin": 15.0,
  "motionWindowMs": 2000
}
```
- **响应示例**：
```json
{
  "code": 200,
  "msg": "本次已更新 2 个运行中的睡岗布控；共享 Pose 模型阈值已更新",
  "updatedControls": ["control-a", "control-b"],
  "globalThresholdsUpdated": true,
  "lastApplied": {
    "preset": "MEDIUM",
    "updatedControls": ["control-a", "control-b"],
    "globalThresholdsUpdated": true,
    "appliedAt": "2026-09-14T08:00:00Z"
  }
}
```

### 4.3 C++ Analyzer 核心控制接口
- **接口地址**：`POST http://<analyzer-host>:<analyzer-port>/api/control/update-algorithm-config`
- **说明**：Java 后端将校验后的参数补丁透传至 C++ 分析引擎。C++ 先更新实际运行布控，再返回本次更新的布控编号；共享 Pose 模型阈值只在至少一个睡岗布控更新成功后修改。
- **响应示例**：
```json
{
  "code": 1000,
  "msg": "algorithm config updated for active sleep controls",
  "updatedControls": ["control-a", "control-b"],
  "globalThresholdsUpdated": true
}
```
