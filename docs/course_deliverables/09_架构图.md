### 图 4：GB/T 28181 注册、保活与点播信令时序图

```mermaid
sequenceDiagram
    autonumber
    participant Dev as 国标设备 (模拟器 :15060)
    participant SIP as GbSipServer (:5060)
    participant ZLM as ZLMediaKit (:9992)
    participant Java as SVA-backend (:9114)
    participant Web as 前端播放器 (Vue)

    %% 注册
    rect rgb(240, 248, 255)
    Note over Dev,SIP: 阶段一：设备注册与认证握手 (SIP REGISTER)
    Dev->>SIP: SIP REGISTER (To: 34020000002000000001)
    SIP-->>Dev: SIP 401 Unauthorized (携带 realm, nonce)
    Dev->>SIP: SIP REGISTER (携带 Digest response 摘要加密校验)
    SIP-->>Dev: SIP 200 OK (注册成功，有效期 3600s)
    SIP->>Java: 设备上线状态同步
    end

    %% 心跳
    rect rgb(245, 255, 245)
    Note over Dev,SIP: 阶段二：定时保活与心跳检测 (Keepalive)
    loop 每 15 秒发送一次心跳
        Dev->>SIP: SIP MESSAGE (<CmdType>Keepalive</CmdType>)
        SIP-->>Dev: SIP 200 OK
        Note over SIP: 重置 45 秒超时倒计时器
    end
    end

    %% 点播
    rect rgb(255, 250, 240)
    Note over Web,Dev: 阶段三：实时视频点播推流 (INVITE)
    Web->>Java: 请求播放地址 (GET /device/list)
    Java-->>Web: 返回播放地址 http://127.0.0.1:9992/live/...
    Web->>ZLM: flv.js 发起 HTTP-FLV 拉流
    ZLM->>SIP: 触发 on_stream_not_found hook
    SIP->>Dev: SIP INVITE (SDP 协商: 请求将视频推至 ZLM 指定 RTP 端口)
    Dev-->>SIP: SIP 200 OK (SDP 响应: 确认视频格式与端口)
    SIP->>Dev: SIP ACK (三次握手确认)
    Dev->>ZLM: RTP/UDP 协议推送封装好 PES PTS 的 MPEG-PS 视频包
    ZLM-->>Web: HTTP-FLV 数据流推送至浏览器
    Web-->>Web: flv.js 纯视频即时解封装渲染
    end
```

### 图 5：GB/T 28181 标准八向云台控制 (PTZ) 交互时序图

```mermaid
sequenceDiagram
    autonumber
    actor User as 操作员 (点击八向雷盘)
    participant Web as SVA-web 前端
    participant Java as SVA-backend
    participant SIP as GbSipServer
    participant IPC as 国标摄像机 (模拟器)

    User->>Web: 鼠标在控制盘上长按【向左上旋转】(速度=48)
    
    par 1. 电子云台视觉毫秒级响应 (前端)
        Web->>Web: CSS transform scale(zoom) translate(-28px, -28px)
        Web->>User: 画面即刻平滑左上平移，显示动作反馈浮层
    and 2. 国标 8 字节 Hex 指令生成与网络下发 (后端)
        Web->>Java: POST /waring/device/ptz/{apeId} {command: "upleft", speed: 48}
        Note over Java: 计算 8 字节指令码:<br/>Byte1=0xA5, Byte2=0x0F, Byte3=0x01<br/>Byte4=0x0A (UpLeft), Byte5=0x30, Byte6=0x30, Byte7=0x00<br/>CheckSum = (Sum & 0xFF) = 0x19<br/>PTZCmd = A50F010A30300019
        Java->>SIP: 组装 SIP MESSAGE <Control><PTZCmd>A50F010A30300019</PTZCmd></Control>
        SIP->>IPC: UDP 投递 SIP MESSAGE 至 :15060
        IPC->>IPC: 解析 PTZCmd 驱动步进电机向左上旋转
        IPC-->>SIP: SIP 200 OK
        SIP-->>Java: 响应完成
        Java-->>Web: HTTP 200 {code: 200, data: {ptzCmd: "A50F010A30300019"}}
    end
    
    Web->>Web: 控制台回显 PTZCmd 编码与执行日志
    
    User->>Web: 鼠标松开方向键
    Web->>Java: POST /waring/device/ptz/{apeId} {command: "stop"}
    Java->>IPC: 下发停止指令 (PTZCmd: A50F0100000000B5)
    IPC->>IPC: 电机制动刹停
```

### 图 6：YOLO-Pose 睡岗姿态识别多帧时序状态转移图

```mermaid
stateDiagram-v2
    direction TB
    [*] --> STATE_STAND: 初始状态 (人员直立/端坐)
    
    STATE_STAND --> STATE_WORK: 坐姿正常工作 (头肩比 Rhs > 0.35, 脊柱倾角 < 25°)
    
    STATE_WORK --> STATE_SUSPECT: 单帧检测到低头/趴桌 (Rhs < 0.15 或 倾角 > 50°)
    note right of STATE_SUSPECT: 启动时序计数器 (Counter++)
    
    STATE_SUSPECT --> STATE_WORK: 连续 15 帧姿态回正 (如喝水、拾物结束)
    note right of STATE_WORK: 判定为瞬时正常动作，Counter 衰减清零 (0 误报)
    
    STATE_SUSPECT --> STATE_SLEEPING: 异常姿态持续超 125 帧 (25fps 下达到 5.0 秒)
    note right of STATE_SLEEPING: 确诊睡岗！锁定该人员目标 Track ID
    
    STATE_SLEEPING --> STATE_ALARM: 触发告警事件生成
    note right of STATE_ALARM: 1. 抓拍绘制骨骼点高清图<br/>2. 截取前后10秒视频切片<br/>3. HTTP POST 上报 Java 入库<br/>4. 进入 60 秒告警静默冷却期
    
    STATE_ALARM --> STATE_SLEEPING: 持续处于睡岗中 (冷却期间不重复轰炸通知)
    
    STATE_SLEEPING --> STATE_WORK: 人员苏醒抬头 (连续 25 帧正常姿态)
    STATE_ALARM --> STATE_WORK: 睡岗结束，状态全面复位
```

### 图 7：视频卡顿与低延迟端到端全链路优化架构图

```mermaid
graph LR
    subgraph S1["1. 源端推流优化 (Source)"]

        O4["PES 0x000001e0 提取<br/>精确硬件时间戳防抖"]
    end

    subgraph S2["2. 中转与网关优化 (Gateway)"]
        G1["TCP 传输 (-rtsp_transport tcp)<br/>100% 杜绝网络丢包花屏"]
        G2["时间戳重生成 (+genpts)<br/>平滑微弱抖动"]
        G3["CBR 码率削峰平谷<br/>防瞬时突发带宽拥塞"]

    end

    S1 --> S2 --> S3 --> S4
```
