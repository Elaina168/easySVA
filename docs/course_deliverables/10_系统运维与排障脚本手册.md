## 一、 文档概述与脚本全景

为了保证 easySVA 平台在开发、测试、演示及生产部署环境中的高可用性与运维敏捷性，系统构建了覆盖**生命周期自愈、国标上下线控制、双流动态转桥守护、全局性能监控及环境平滑切换**的完整脚本工具链。

系统所有脚本统一放置于运行根目录下（开发目录 `/opt/SVA-dev/`，成品目录 `/opt/SVA/`），两套环境严格保持 1:1 双向对齐。

## 二、 全栈生命周期管理脚本

### 2.1 全系统一键自愈重启：`restart.sh`
- **文件路径**：`/opt/SVA-dev/restart.sh`、`/opt/SVA/restart.sh`
- **执行命令**：
  ```bash
  sudo bash /opt/SVA-dev/restart.sh
  ```
- **核心逻辑流程**：
  1. **优雅停止与端口清场**：按顺序 `pkill` 停止 `gb_bridge_daemon`、`webcam_bridge`、模拟器进程、Analyzer、Java 后端、ZLMediaKit；并通过 `fuser -k -9` 强力释放关键端口（9114、9992、9993、9994、9995、18080、SIP 5060）。
  2. **启动 ZLMediaKit (MediaServer)**：启动并在 20 秒内轮询 `getServerConfig` 探针确认就绪。
  3. **启动 GbSipServer 信令服务**：注入配置密码，启动并在 20 秒内轮询 `18080/gb28181/api/devices` 确认 HTTP API 与 SIP UDP 5060 就绪。
  4. **拉起视频源与双国标模拟器**：
     - 启动 `live/sleep_test` 本地测试推流；
     - 启动设备 1（西门高精度球机，SIP: 15060，媒体: 30000）；
     - 启动电脑摄像头 WebSocket 中继服务（`webcam_bridge.py :18090`）；
     - 启动设备 2（电脑摄像头模拟器，SIP: 15062，媒体: 30002）；
     - 启动双国标高可用转推守护进程 `gb_bridge_daemon.sh`。
  5. **启动 C++ Analyzer 分析引擎**：载入 `config.json`，探测 `9993/api/health` 确认引擎健康。
  6. **启动 Java Spring Boot 后端**：启动 `backend.jar`，探活 `9114/login` 确认服务可用。
  7. **自愈布控任务恢复**：调用 `auto_recover.sh` 恢复历史任务。

### 2.2 自动恢复与代理重建：`auto_recover.sh`
- **文件路径**：`/opt/SVA-dev/auto_recover.sh`
- **执行命令**：
  ```bash
  bash /opt/SVA-dev/auto_recover.sh
  ```
- **核心逻辑**：
  - 系统冷启动后，ZLMediaKit 的内存代理流会丢失；
  - 脚本从 MySQL `h_device` 读取所有 `stream_source_type='DIRECT'` 的设备，自动重新向 ZLM 发起 `addStreamProxy` 请求；
  - 检索 `h_alarm_task` 中原状态为 `RUNNING` 的布控，通过调用 Java 后端 `startMonitor` 接口实现无人值守自愈。

## 三、 国标 GB28181 设备上下线运维脚本

为了方便评测老师与测试人员对国标信令、注册超时、心跳检测与断网重连进行直观验证，系统重构了专门的上线与下线脚本。

### 3.1 国标设备上线脚本：`device_online.sh`
- **文件路径**：`/opt/SVA-dev/device_online.sh`
- **用法规范**：
  ```bash
  bash device_online.sh [1|2|all]
  ```
  - `bash device_online.sh 1`：仅通电并上线**设备 1（西门高精度球机）**；
  - `bash device_online.sh 2`：仅通电并上线**设备 2（工位电脑摄像头）**；
  - `bash device_online.sh all`（或不传参）：一键上线全部国标设备。
- **特性保障**：
  - **幂等性防重**：内置进程检查，若模拟器已在运行，打印 PID 并跳过重复拉起，杜绝端口冲突。
  - **自动状态写回**：启动模拟器并等待 2 秒完成 SIP REGISTER 握手后，脚本自动调用 Java 后端 `/waring/device/gb28181/sync` 接口，将在线状态（1）写回 MySQL。
  - **格式化终端表格**：终端自动输出当前所有国标设备的最新状态表：
    ```text
    >> 数据库中所有国标设备当前状态如下：
    设备名称                         国标编码               端口    在线状态    最近心跳
    西门高精度国标球机(本地视频源)   34020000001320000001   15060   在线 (1)    2026-09-10 17:14:40
    工位实景国标摄像头(电脑摄像头)   34020000001320000003   15062   在线 (1)    2026-09-10 17:14:39
    ```

### 3.2 国标设备模拟下线脚本：`device_offline.sh`
- **文件路径**：`/opt/SVA-dev/device_offline.sh`
- **用法规范**：
  ```bash
  bash device_offline.sh [1|2|all]
  ```
  - `bash device_offline.sh 1`：仅下线设备 1，设备 2 保持在线；
  - `bash device_offline.sh 2`：仅下线设备 2，清理后台守护，设备 1 不受影响；
  - `bash device_offline.sh all`（或不传参）：下线全部国标设备。
- **特性保障**：
  - **优雅 SIP 注销**：定向发送 `SIGTERM` 信号，模拟器触发 `REGISTER Expires: 0` 注销握手，GbSipServer 瞬间将其从活跃设备池移除。
  - **清理死循环 Guard**：彻底清除历史守护 PID，杜绝离线后被意外自动拉起。
  - **联动转桥停推**：转桥服务检测到设备下线后，立即停用 FFmpeg 转推，无报错刷屏。
  - **数据库即时同步**：自动调用后端接口更新 `is_online = '0'`。

## 四、 流媒体转推与中继守护脚本

### 4.1 双国标流动态转桥守护：`gb_bridge_daemon.py`
- **服务角色**：国标 RTP 流 -> 规范实时直播流的桥梁与自愈核心。
- **工作机制**：
  1. **设备注册状态感知**：每 2 秒查询 `GET /gb28181/api/devices`。若设备离线，**严禁发起盲目点播**，并立即平稳杀死已有 FFmpeg 转推进程，彻底解决 HTTP 404/409 日志刷屏；
  2. **智能点播与防抖**：设备恢复在线后，若检测无活跃点播会话，自动向 GbSipServer 请求 `POST /gb28181/api/live/start`，并设置 5 秒调用防抖；
  3. **实时零延迟转推**：以 `-rtsp_transport tcp` 接入 ZLM `rtp/` 流，使用 `-c:v libx264 -preset ultrafast -tune zerolatency` 规整时间戳并转推至固定目标地址：
     - 设备 1：`live/gb_34020000001320000002_0100000016`
     - 设备 2：`live/34020000001320000003`
  4. **断流超时自愈**：当 ZLM RTP 端口连续 3 次无数据流时，判定端口失效，自动调用 `live/stop` 关闭失效会话并触发会话重建。

### 4.2 电脑摄像头推流中继：`webcam_bridge.py`
- **服务角色**：解决无实体硬件摄像头环境下的浏览器真实视频采集注入。
- **监听端口**：WebSocket `18090`。
- **工作机制**：
  - 接收来自 Chrome/Edge 浏览器导航栏【开启电脑摄像头】推送的 WebM 数据包；
  - 通过 Linux 管道直接输入 FFmpeg，转封装推流至 ZLM `rtmp://127.0.0.1:9995/live/webcam`；
  - 当无浏览器推流时，自动维持内置测试彩条（1280x720, 25fps），保证下游国标设备 2 的推流输入永不中断。

## 五、 系统监控与诊断排障脚本（重点监控工具）

平台设计了 3 款轻量、只读、递进式的命令行监控与抓包诊断脚本，供开发与答辩评审快速研判系统健康度：

### 5.1 国标设备专项实时监控看板：`gb_monitor.sh`
- **文件路径**：`/opt/SVA-dev/gb_monitor.sh`
- **启动命令**：
  ```bash
  # 持续交互看板（每 2 秒自动刷新，彩色终端呈现）
  bash /opt/SVA-dev/gb_monitor.sh

  # 单帧自检模式（用于自动化巡检或脚本采集）
  ONESHOT=1 bash /opt/SVA-dev/gb_monitor.sh
  ```
- **核心监视指标**：
  1. **注册与心跳倒计时**：双设备 IP/端口、User-Agent、注册耗时、心跳衰减倒计时（超过 30s 变黄预警，超过 45s 标红判定离线）；
  2. **SIP 点播会话 (Sessions)**：展示当前所有点播流的状态、SSRC、媒体端口、推流持续时长；
  3. **信令统计与关键日志**：统计心跳、注册、INVITE、PTZ 累计次数，并实时抓取设备端最新信令；
  4. **最近云台 PTZ 动作**：清晰解析并打印最新下发的云台方向与速度。

### 5.2 easySVA 系统全景监控看板：`sva_monitor.sh`
- **文件路径**：`/opt/SVA-dev/sva_monitor.sh`
- **启动命令**：
  ```bash
  # 持续交互看板（每 2 秒自动刷新）
  bash /opt/SVA-dev/sva_monitor.sh

  # 单帧自检模式
  ONESHOT=1 bash /opt/SVA-dev/sva_monitor.sh
  ```
- **核心监视指标**：
  1. **6 大核心服务 HTTP/端口探活**：
     - ZLMediaKit (:9992)、GbSip (:18080)、Analyzer (:9993)、Java 后端 (:9114)、Nginx (:80)、MariaDB (:3306)；绿色 `● OK` / 红色 `● DOWN`。
  2. **后台关键进程存活与 PID**：精确识别 MediaServer、GbSipServer、Analyzer、Java 及 FFmpeg 推流转桥进程。
  3. **实时业务指标联动**：活跃布控任务状态（如 `[RUNNING]`）、当前推拉流总路数及流 ID 列表、累计告警条数与最新告警时间、系统 CPU/内存/负载。

### 5.3 云台 PTZ SIP 信令抓包与智能解码器：`ptz_capture.sh`
- **文件路径**：`/opt/SVA-dev/ptz_capture.sh`
- **核心背景**：国标云台控制由 Java 后端直接向设备的 UDP 15060/15062 发送 SIP MESSAGE。本工具专门针对该路径进行抓包与 8 字节 Hex 解码。
- **三种使用模式**：
  ```bash
  # 1. 智能抓包模式（在终端启动后，去网页端点按云台方向键，终端秒级解析）
  bash /opt/SVA-dev/ptz_capture.sh

  # 2. 原始报文模式 (类似精简版 Wireshark)
  bash /opt/SVA-dev/ptz_capture.sh --raw

  # 3. 主动发包并自测抓包（无需打开浏览器）
  bash /opt/SVA-dev/ptz_capture.sh --fire 34020000001320000003 right
  ```
- **抓包结果示例**：
  ```text
  [PTZ] 收到国标云台控制指令: 
    - 原始指令: PTZCmd=A50F0101200000D5
    - 解析动作: 向右旋转 (Pan Right)
    - 水平速度: 32 (0x20)
    - 校验和:   D5 (校验正确 OK)
  ```

## 七、 常见故障排查（FAQ）

1. **执行脚本提示 `Permission denied`**：
   - 确保使用 `bash script_name.sh` 执行，或使用 `chmod +x *.sh` 赋予可执行权限；若涉及端口 80 或系统进程终止，前置 `sudo` 执行。
2. **国标模拟器无法注册上线**：
   - 运行 `ONESHOT=1 bash gb_monitor.sh` 检查 GbSipServer 18080 与 5060 是否正常；
   - 检查 `simulator.log` 中是否收到 401 质询及是否回送 Digest Authorization 头。
3. **推流卡顿或浏览器黑屏**：
   - 确认 `gb_bridge_daemon.py` 正在后台运行（`ps aux | grep gb_bridge`）；
   - 查看 `/opt/SVA-dev/gb_bridge.log` 中是否存在 `[BridgeDaemon] 启动转推` 成功日志。
