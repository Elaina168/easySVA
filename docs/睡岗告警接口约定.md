# 睡岗告警上报接口约定（任务四 → 任务二联调）

> 本文档约定任务二（C++ 侧）上报睡岗告警到任务四（Java 后端）的字段格式。
> 后端按此约定已实现 `POST /waring/waring/addFromSvaSimple` 的睡岗识别与入库。
> **待任务二确认**：实际 C++ 上报 JSON 是否与下表字段一致；不一致时以本表为基准调整映射。

## 接口

- 路径：`POST /waring/waring/addFromSvaSimple`
- 认证：`Authorization: Bearer <token>`
- Content-Type：`application/json`

## 请求字段

| 字段 | 类型 | 必填 | 说明 |
|------|------|------|------|
| `control_code` | string | 是 | 布控唯一标识（如 `controls2NmNxDkWsgKX8`） |
| `behavior_type` | string | 是 | 行为类型；睡岗为 `sleep` 或 `sleep_post` |
| `alarm_type` | string | 否 | 告警类型；传入 `sleep` 时与 `behavior_type` 等价识别 |
| `image_path` | string | 是 | 截图路径（相对/绝对均可），后端写入 `picture_url` / `picture_absolute_url` |
| `alarm_time` | string | 是 | 告警时间，格式 `yyyy-MM-dd HH:mm:ss` |

## 识别规则（后端已实现）

1. `behavior_type`（或 `alarm_type`）命中 `sleep` / `sleep_post` / 含"睡岗" → 记为 `SVA_SLEEP`，显示名"睡岗告警"；
2. 否则记为 `SVA_SIMPLE`，显示名"SVA告警"，兼容原普通告警链路；
3. 截图写入 `picture_url`（原始路径）与 `picture_absolute_url`（解析后的绝对地址）。

## 示例请求

```json
{
  "control_code": "controls2NmNxDkWsgKX8",
  "behavior_type": "sleep",
  "alarm_type": "sleep",
  "image_path": "/tmp/sleep_alarm.jpg",
  "alarm_time": "2026-09-02 19:21:00"
}
```

## 查询

按告警类型过滤：`GET /waring/waring/list?alarm_type=SVA_SLEEP`
