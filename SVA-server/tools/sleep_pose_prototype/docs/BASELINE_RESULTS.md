# 睡岗检测原型 v0.1 基线结果

## 验证范围

- 验证日期：2026-09-04
- 环境：Ubuntu 24.04 虚拟机、Python 虚拟环境、CPU 推理
- Pose 模型：`yolo11n-pose.pt`
- 配置：`config/default.yaml`
- 告警策略：15 秒窗口、有效帧比例不低于 60%、候选姿态比例不低于 80%

本轮使用的是公开场景素材，用于确认程序、姿态规则和时序状态机能够完整运行。样本数量较少且不是目标摄像头采集数据，因此结果只能称为功能基线或冒烟测试，不能作为生产准确率。

## P02 边界样本

为了单独检查时间条件，将 P02 循环生成约 22 秒的派生视频。该视频仍未告警，逐帧统计如下：

- 总检测数：550
- 睡岗候选帧数：0
- 550 帧的判定原因均为 `head_not_low`
- `head_height_ratio`：最小值 0.521，中位数 0.537，最大值 0.558
- 当前 `head_height_ratio_max`：0.45

这说明 P02 不是因为原视频太短而漏报，而是“手托脸但头部仍较直立”的姿态不属于当前规则。现阶段不为单一样本放宽头部高度阈值，避免把阅读、看手机和托腮思考引入误报。若业务后续明确要求覆盖这一类姿态，应增加独立的扶脸型时序规则，并结合更多负样本评估；如需可靠区分闭眼和思考，仅使用 COCO 17 点 Pose 不足以完成判断。

循环视频只用于验证规则覆盖范围，不计入正式样本数量或准确率统计。

## 告警证据检查

- P01：`head_low+side_lean+head_near_arm+shoulder_tilt`
- P03：`head_low+shoulder_tilt+low_motion`
- P04：`head_low+head_near_arm+shoulder_tilt+low_motion`
- P05：`head_low+head_near_arm+shoulder_tilt+low_motion`

告警证据与视频中的趴伏、侧倾、靠手臂及低运动姿态一致。P01、P05 在完整 15 秒确认窗口后告警；P03、P04 从视频起点计算约 19 秒后告警，说明窗口内候选帧比例需要累积到设定阈值。

## ONNX 交付验证

模型已使用固定输入尺寸、无内置 NMS 的方式导出，并通过 ONNX Runtime CPU 实际执行：

| 项目 | 实际值 |
| --- | --- |
| 文件 | `models/yolo11n-pose.onnx` |
| 文件大小 | 约 12 MB |
| Opset | 17 |
| 输入节点 | `images` |
| 输入张量 | `[1, 3, 640, 640]`、`tensor(float)` |
| 输出节点 | `output0`（该基线模型实测值） |
| 输出张量 | `[1, 56, 8400]`、`tensor(float)`（该基线模型实测值） |
| 动态尺寸 | 否 |
| 内置 NMS | 否 |

输入图像来自 OpenCV BGR，预处理交换通道为 RGB，形成 NCHW、float32、数值范围 `[0, 1]` 的张量，并使用保持宽高比的 letterbox 和填充值 114。C++ 实现按 ONNX Runtime 实际读取的节点名和维度工作，允许 `[1, 56, N]` 与 `[1, N, 56]` 两种布局，并自行实现置信度过滤、Pose 输出解码、NMS 和 letterbox 坐标逆变换。

## 下一阶段

阶段二 C++ CPU 冒烟测试已在同一虚拟机完成：P01 共 591 帧、591 次人物检测，处理 51.102 秒，吞吐率 11.565 FPS；人框与关键点位置正确。与 Python 原型约 16.663 FPS 相比速度较低，但足以支持当前建议的每路 3–5 FPS 行为抽帧。该数字只代表当前虚拟机 CPU，不能外推到生产硬件。
