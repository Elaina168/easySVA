# 任务一交付与协作边界说明

## 1. 文档目的

本文用于说明“任务一｜睡岗算法原型”的正式交付范围，并区分本次开发中为联调提前完成的任务二内容。本文只描述工作归属，不否定或删除已经验证通过的 C++ 与平台集成成果。

## 2. 任务一正式职责

任务一负责睡岗算法原型，不负责 GB28181 接入、Java 后端、数据库或 Vue 前端开发。正式职责包括：

1. 基于 YOLO-Pose 识别人体及 17 个 COCO 人体关键点；
2. 计算头部、肩部、躯干、头部与手臂距离及运动量等二维姿态特征；
3. 使用 `NORMAL/SUSPECT/SLEEP/RECOVER` 多帧状态机过滤瞬时低头；
4. 使用本地视频完成正负样本验证并记录阈值边界；
5. 导出 ONNX 模型，记录输入输出、预处理、关键点编号和坐标还原方法；
6. 将模型与判定逻辑作为任务二 C++ 集成的标准输入。

## 4. 额外完成的任务二内容

为了尽早验证任务一的 ONNX 和判定逻辑，本次开发提前完成了以下 C++ 集成工作。这些内容超出任务一的最低交付范围，应作为任务二负责人的可复用成果移交：

- `AlgorithmOnYoloPose`：ONNX Runtime 推理、输出解析和 17 点坐标还原；
- `SleepPoseEvaluator`：C++ 特征提取与睡岗状态机；
- `Analyzer/Scheduler/Worker`：`on_yolo11n_pose` 注册、逐流状态隔离和行为规则接入；
- `PoseSmokeTest`、`SleepPoseUnitTest`：C++ 冒烟测试与单元测试；
- 睡岗事件接入原有告警上报、截图和录像链路；
- RTSP 输入上的平台正负样本验证及原 YOLO 回归。

上述代码当前已验证可用，不需要因为职责调整而回退。移交后，其后续维护、GB28181 流兼容和断线重连由任务二负责人承担。

## 5. 尚不属于任务一的工作

以下内容不作为任务一是否完成的判定条件：

| 工作内容 | 责任任务 |
| --- | --- |
| GB28181 SIP 注册、心跳、Catalog、INVITE、RTP 推流 | 任务三 |

| 国标设备同步、设备状态、数据库字段与告警入库 | 任务四 |
| 设备页面、国标预览、睡岗选项和告警展示 | 任务五 |
| RTSP/GB28181 全系统最终联调 | 任务五组织，各模块负责人配合 |

任务一与任务二之间只需保持以下接口稳定：

- 输入：RGB、NCHW、`float32`、`[1,3,640,640]`、数值范围 `[0,1]`；
- 输出：节点 `output0`、`[1,56,8400]`、无模型内 NMS；
- 关键点：COCO 17 点，每点为 `(x, y, confidence)`；
- 几何恢复：严格使用 letterbox 的缩放比例与 padding；
- 判定参数：以 `config/default.yaml` 和 `IO_CONTRACT.md` 为准。

## 6. 验证结论与限制

当前 9 段公开素材足以验证程序结构、ONNX 可执行性、状态机逻辑和首轮阈值边界，可以支撑“算法原型”阶段验收，但不足以证明生产环境泛化精度。

当前结论不得表述为“模型已经达到生产准确率”。推荐表述为：

> 已完成基于 YOLO-Pose 的睡岗检测原型、ONNX 导出和本地正负样本功能验证；首轮样本能够区分持续睡岗与普通阅读、工作、写字场景。算法仍需使用目标机位采集的独立数据集继续评估遮挡、多人、视角和光照条件下的误报率与召回率。

目标机位数据建议至少继续覆盖：短时低头、长时间阅读、托腮思考、趴桌、侧靠、双肩遮挡、多人交叉、人员离开、弱光和摄像头抖动。
